# Artemis Case 工作区整合说明

入口为 `index.html`。直接打开即可使用，不需要安装依赖。以 1440 × 900 桌面窗口为主要布局，左右比例可拖动调整。

## 本轮页面关系

主要路径已收缩为 **列表 → Case 工作区**。

- 列表中的名称和行主体直接打开工作区。
- 未执行时展示目标、输入区和等待连接的设备区域。
- 执行中展示当前消息流与设备直播。
- 已结束时打开最近运行，消息流末尾展示结束结论、未完成事项和证据入口。
- 标题附近的选择器切换历史运行，保持同一套工作区。
- 测试目标位于顶部可展开区域；“编辑”仅修改 Case 名称、目标、分类、标签和补充说明。
- 旧的运行详情和复盘链接兼容进入对应的 Case 工作区，不再保留独立中间页。

返回 Cases 会保留分类、搜索、标签、创建人、归档筛选、排序及列表滚动位置。离开工作区不会停止运行。关闭整个页面后，本地模拟暂停，重新打开时等待继续，不编造离线期间的执行结果。

## 创建与设备选择

“新建 Case”直接进入空工作区，在底部填写“这次想测试什么”。名称默认从首句提取，也可通过编辑修改；不会冒充调用模型生成了名称。

提交目标后：

1. 保存 Case 与待执行意图，用户目标出现在左侧消息流。
2. 在同一位置出现“选择执行设备”卡片。
3. 设备展示名称、平台及连接／可用状态。占用和离线设备不能开始。
4. 选择可用设备并开始后才创建运行编号，卡片收起为“已使用某设备”。
5. 后续动作、验证、重试和输出继续进入消息流。

无可用设备时，卡片内提供刷新与连接指引。当前列表为本地示例设备，未接入真实设备发现服务。

新运行默认 HappyCoding、自动执行，测试账号由演示逻辑处理，视频和日志默认保留。界面已移除模型／工具选择、账号选择、版本、构建号、执行方式和保留策略配置。历史快照中的原值不被新默认值覆盖。

## 消息流与证据

左侧从阶段目录改为按发生时间排列的消息流：

- 用户目标与补充指令。
- 设备选择和已使用设备记录。
- 原项目中已有的示例输出。
- Action、结果校验、首次失败、重试、恢复和计划调整。
- 运行结束结论及相关证据入口。

较长输出可展开全文，工具参数和原始记录默认折叠。当前或选中的记录与异常记录提供更大的结果图，其他记录使用缩略图。点击图片才打开图片查看；选中消息、展开文字或工具记录都不切走右侧直播。

新演示事件用明确的 `actionId` 关联校验与动作；旧版中由本原型生成、具有确定事件编号的记录补充同一关联。没有明确关联的内容不会仅按“步骤 3”猜测绑定。

**决策截图与动作结果截图分开表达。** 决策截图表示模型调用实际输入；本次可访问数据没有这类真实原始截图，因此明确显示缺失，不把操作前画面或结果图替代为模型输入。动作结果图片沿用已有示例重建画面，标注来源。

旧版自动生成的“阶段目标”模板不再作为原始模型输出展示。原执行详情中的“仍停留在邮箱页。等待后再次点击‘下一步’。”保留其示例性质，显示为“原项目示例输出”，不冒充真实调用记录。

当用户上翻阅读历史消息时，新事件仅增加提示，不重绘正在阅读的消息。点击“回到最新”后统一更新；右侧直播仍独立刷新。补充指令保持提交与记录状态，未获得真实反馈时不标记“已被采纳”。

## 直播、TaskPlan 与回放

右侧始终保留“直播 / TaskPlan / 回放”三个位置。

- 工作区默认打开直播，设备画面保持完整比例。
- 运行结束后直播位置显示“本次执行已结束”，保留最后可用画面和回放入口。
- 连接中断时显示最后画面时间与重新连接入口；任务状态单独显示。
- TaskPlan 支持独立查看，也可与直播同时展示；分屏宽度不足时改为上下排列。
- 回放按已记录的画面事件定位，并可跳到关联消息；这是事件回放，不是真实录屏视频。

TaskPlan 渲染器递归保留原始字段、数组和对象层级，可表达层级任务、状态、循环、校验／断言以及自由文本，并支持已提供的计划版本和调整记录。不会把任务状态汇总成测试通过率。

**当前数据边界：可访问的三个原型没有保存完整原始 TaskPlan。** 管理原型只有三条通用计划，执行与整合原型主要是五阶段数组。因此现有记录显示“仅有阶段摘要”，保留已有预期与状态，以及已记录的等待／重试调整；不补写或伪装成完整原始计划。若后续数据提供 `taskPlan`、`task_plan`、`rawTaskPlan` 或 `planVersions`，工作区直接按其原始内容展示。

## 管理入口的变化

已移除全局竖栏、Case 操作大弹窗、横向五阶段条、“定位异常”主按钮、独立结果复盘页、独立运行配置表和说明性大卡片。

行尾更多菜单保留编辑、移动、归档和恢复。归档含义为“从常用列表收起，保留定义和历史，可以恢复”；归档入口不使用醒目的红色按钮，已归档内容通过列表筛选查找。

原有分类、搜索筛选、只读权限与控制权提示继续保留。历史 Case 数据和备注不删除；本轮只调整工作区的主要入口与展示结构。

## 文件

- `index.html`：统一产品入口。
- `app.js`：列表、工作区、消息流、设备卡片、计划面板和导航。
- `model.js`：数据兼容、意图提交、运行快照、事件和模拟执行。
- `ui-assets.js`：共享图标与延续的示例设备画面。
- `styles.css`：统一视觉、分栏和响应式布局。
