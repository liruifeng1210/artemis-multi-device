# Artemis 探索工作区

直接打开 `index.html`。本轮把管理首页和创建属性表替换为 **可收起的 Case 侧栏 + 探索主区域**，保持本地、可编辑的静态原型形式。

## 页面与主要转场

- 首次进入：侧栏列出已有 Case，主区域直接显示产品、环境、平台和探索输入框。
- 新建 Case：进入空白探索草稿并聚焦输入框。不要求名称、前置条件、账号或设备；首次提交才保存 Case，以目标首句暂命名。
- 未提交的非空草稿可在侧栏恢复。反复新建空草稿不会产生永久 Case。
- 提交目标：在原工作区展开消息流与观察区，目标成为首条用户消息，输入框移至底部，消息中出现设备卡片。
- 设备确认：生成本次探索记录，设备卡片保留为已使用设备记录，开始模拟执行。
- 执行结束：结论仍在原消息流末尾，直播位置保留结束状态与最后画面，并提供回放。
- 点击侧栏 Case：直接打开当前探索；没有进行中探索时打开最近记录；只有草稿时恢复目标和上下文。
- 历史探索通过顶部选择器切换，不经过记录列表或定义详情页。

## 产品、环境与平台

产品目录是明确标记的原型示例，不代表真实服务：

| 产品 | 环境 | 可选平台 |
| --- | --- | --- |
| 协作空间（示例） | Staging、Test | Android、iOS |
| 客户门户（示例） | Dev、Sandbox | Android |

首次使用需要明确选择产品，不根据目标自动匹配。之后沿用最近有效组合。切换产品时，环境和平台更新为可用选项，并给出反馈，目标文本保留。

- 提交前：可以修改产品、环境与平台。
- 等待设备：修改后更新待执行快照、刷新候选并清除设备选择。
- 执行中：当前上下文固定。
- 查看历史：显示当时的产品、环境、平台和设备；底部的“下一次探索”选择只用于下一次提交。
- 旧记录缺少的产品信息标为未记录，不用新默认值覆盖历史。

模型固定 HappyCoding；账号由内部自动获取；视频与日志默认保留。原型没有相关选择器或保留开关，真实服务尚未接入。

## 设备卡片

设备只在提交后的消息流中选择。支持加载、可用、占用、离线、无可用设备、刷新、准备执行和确认后的记录状态。

候选按所选平台过滤，活动探索使用中的设备显示占用，不能再次确认。不同 Case 可以使用不同可用设备同时运行。客户门户的 Sandbox 环境演示无可用设备情况，卡片内有刷新与连接指引。

连接状态与探索状态分别表达。直播断开后保留最后画面时间；网络恢复后可重连，任务不会因直播断开自动停止。

## 消息、截图与计划

沿用此前的执行消息、动作结果、失败证据、恢复校验、技术记录和回放组件。主要内容直接可读，长文本可展开，底层记录默认折叠。

新增的邮箱登录演示包含：

1. 打开登录页、输入邮箱。
2. 首次点击下一步后未出现密码页，保留验证失败证据。
3. 等待后重试，进入密码页并展示恢复。
4. 完成登录并验证首页。

新增输出明确标记为模拟；模拟决策截图与动作结果截图分别关联具体调用或动作，不互相冒充。旧记录缺少模型输出、决策截图或完整 TaskPlan 时仍说明缺失，不补造成系统原始记录。

新增演示 TaskPlan 包含任务分组、子任务、有界重试循环、检查与断言、状态和调整记录。当前计划随执行更新，支持查看历史版本及跳转到关联消息。计划状态不是测试通过率。历史中只有阶段摘要的记录继续如实展示摘要。

右侧始终保留直播、TaskPlan 和回放，可并排查看直播与计划。点击左侧记录或展开日志不切走直播；放大截图使用独立查看层。回放按已记录画面和事件推进，不宣称是真实录屏。

## 状态连续性

- 新建、切换 Case、切换历史、收起侧栏不停止探索。
- 输入草稿与阅读位置保存；新事件不抢占上翻位置，提供“回到最新”。
- 补充指令归属当前探索，并明确标记采纳未确认。
- 结束后的输入区使用“再次探索”按钮；提交后重新选择设备，创建新记录并保留旧记录。
- 侧栏按最近使用排序，支持搜索、重命名、归档和恢复。归档只从常用列表收起，保留历史。
- 窄窗口默认收起侧栏；侧栏隐藏后顶部仍有展开和新建入口。观察区可收起，双栏宽度支持拖动和键盘调整。
- 关闭页面后本地模拟暂停，重新打开需要继续，不编造离线执行结果。

## 验收结果

使用独立、隔离的无界面 Edge 浏览器运行了本地交互脚本，没有改动用户浏览器中的 Case 数据。

主流程 34 项检查通过，覆盖十项请求路径：初始布局、联动上下文、首条消息与双栏转场、设备过滤和无设备状态、补充指令、完成结论、TaskPlan、截图查看、回放、历史切换、再次探索、并行 Case、草稿恢复、阅读位置、侧栏收放、重命名、归档恢复及浏览器运行错误检查。

补充检查验证了断线重连、最新计划状态、停止时计划快照和键盘调整双栏。浏览器实际视口 994px 与 504px 下，输入、执行和结束状态没有页面横向溢出。另通过了 JavaScript 语法及模型状态测试，包括产品组合校验、设备平台过滤、运行时上下文固定、历史隔离与新探索编号。

没有连接真实 Agent、产品目录、设备、模型或账号服务。邮箱登录场景可完整模拟；其他自定义目标记录目标与设备后等待执行接入，不自动编造成功结果。

## 源码

- `index.html`：唯一产品入口。
- `app.js`：Case 侧栏、草稿、上下文、转场和交互状态。
- `exploration-model.js`：产品目录、上下文约束、探索草稿、设备候选与明确标记的演示数据。
- `model.js`：保留的 Case／历史模型及邮箱登录执行脚本。
- `workspace-renderers.js`：消息、证据、TaskPlan 和回放组件。
- `ui-assets.js`：一致的线性图标与示例设备画面。
- `styles.css`、`explorer.css`：复用组件样式与探索工作区布局。
